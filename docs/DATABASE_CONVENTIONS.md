# Database Conventions — JAAGO Foundation ERP v2.0

> Last updated: 2026-08-16

## ORM

**Drizzle ORM** is the only ORM. Prisma is NOT used (would create dual migration sources).

**Supabase CLI** is the single migration runner. All schema changes go through:
```
supabase/migrations/YYYYMMDDHHMMSS_description.sql
```

Never edit production tables manually. Never run raw SQL migrations outside of Supabase CLI.

## Naming Conventions

| Object | Convention | Example |
|---|---|---|
| Tables | `snake_case`, plural | `leave_requests`, `purchase_orders` |
| Columns | `snake_case` | `created_at`, `org_id`, `employee_code` |
| Primary keys | `id` (UUID/CUID) | `id uuid PRIMARY KEY DEFAULT gen_random_uuid()` |
| Foreign keys | `{referenced_table_singular}_id` | `department_id`, `employee_id` |
| Indexes | `idx_{table}_{columns}` | `idx_employees_org_id_status` |
| Policies | `{table}_{policy_name}` | `employees_tenant_isolation` |
| Constraints | `{table}_{column}_{constraint_type}` | `leave_requests_status_check` |

## Mandatory Columns on Every Business Table

```sql
id              UUID PRIMARY KEY DEFAULT gen_random_uuid()
org_id          UUID NOT NULL REFERENCES organizations(id)
created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
created_by      UUID REFERENCES users(id)
updated_by      UUID REFERENCES users(id)
deleted_at      TIMESTAMPTZ  -- soft delete (NULL = not deleted)
```

Additional where meaningful:
- `office_id` — if record belongs to a specific office
- `department_id` — if record belongs to a department
- `project_id` — if record belongs to a project
- `version` — optimistic concurrency lock (integer, incremented on each update)

## ID Strategy

- **Internal IDs:** UUID (PostgreSQL `gen_random_uuid()`) — used in DB, foreign keys, API
- **Human-readable codes:** separate `reference_number` or `code` column — shown in UI
- IDs are never exposed in URLs for sensitive entities (use reference numbers)

## Row-Level Security (RLS)

**RLS is ENABLED AND FORCED on every business table.** No exceptions.

Every table has at minimum:
```sql
ALTER TABLE {table} ENABLE ROW LEVEL SECURITY;
ALTER TABLE {table} FORCE ROW LEVEL SECURITY;

CREATE POLICY "{table}_tenant_isolation" ON {table}
  FOR ALL
  USING (org_id = current_setting('app.current_org_id')::uuid);
```

The tenant context is set by `apps/api` at request start:
```sql
SET LOCAL app.current_org_id = '{org_id}';
SET LOCAL app.current_user_id = '{user_id}';
SET LOCAL app.current_role = '{role}';
```

**Cross-org tests are written BEFORE RLS policies** in Phase 2 — they must fail without policies, then pass after.

## Indexing Requirements

All tables must have:
- Primary key index (automatic)
- `(org_id, created_at DESC, id)` composite index for list queries
- Index on `status` column where present
- Index on `deleted_at` (partial: WHERE deleted_at IS NULL)
- Index on any column used in common filter queries

Additional for specific tables:
- `employees`: index on `email`, `employee_code`, `department_id`, `status`
- `purchase_requests`: index on `reference_number`, `department_id`, `status`, `requested_by`
- `audit_log`: index on `(org_id, entity_type, entity_id)`, `(org_id, created_at)`, `user_id`

## Pagination

**Cursor pagination only** for large tables. Never offset pagination for business data.

The repository base class enforces a mandatory `limit` parameter. Unbounded queries throw:
```typescript
// This THROWS in the base repository
repository.findMany({ where: { orgId } }); // ❌ no limit

// This is REQUIRED
repository.findMany({ where: { orgId }, limit: 50, cursor: '...' }); // ✓
```

Default page size: 50 rows. Maximum: 200 rows.

## Money Storage

```sql
amount          NUMERIC(15, 4) NOT NULL  -- never FLOAT
currency_code   VARCHAR(3) NOT NULL DEFAULT 'BDT'
```

- Store `amount + currency_code` together — never store amount alone
- Server computes all totals — never trust totals from the browser
- Historical FX rates stored in `fx_rates` table — never recompute historical amounts
- `Available = Approved Budget - Committed - Spent` computed server-side

## Timestamp Storage

- **All timestamps stored in UTC** (`TIMESTAMPTZ`)
- Business dates (leave dates, fiscal dates) stored as `DATE` in the org's timezone
- UI renders timestamps in the user's/org's configured timezone
- No timezone-dependent business logic in client components

## Soft Deletes

Business records that need historical preservation use soft delete (`deleted_at IS NOT NULL`).

Records that should be physically deleted (temp uploads, sessions) use hard delete.

Drizzle queries filter `deleted_at IS NULL` by default in the base repository.

## Audit Fields

Every business mutation writes to `audit_log`:
- `user_id` — who performed the action
- `action` — verb (CREATE, UPDATE, DELETE, APPROVE, REJECT, etc.)
- `module` — which module
- `entity_type` — table name
- `entity_id` — PK of affected row
- `old_values` — JSONB snapshot before change (where relevant)
- `new_values` — JSONB snapshot after change
- Audit log is **append-only**, enforced at DB level (no UPDATE/DELETE grant for app role)

## High-Volume Table Partitioning

These tables are partitioned by time (range on `created_at`):
- `audit_log` — partitioned by month
- `app_log` — partitioned by day
- `api_request_log` — partitioned by day
- `security_events` — partitioned by month

Retention = **DROP old partitions** (instant, no expensive DELETE).

## Migration Guidelines

1. Never edit production tables manually
2. Every column addition is backwards-compatible (nullable or with DEFAULT)
3. Dropping columns: deploy compatible code first → migrate → verify → remove field from code
4. Destructive migrations flagged explicitly in CI (shadow DB check)
5. Migrations run against a shadow DB in CI and block on failure
6. Before creating any table: check if equivalent exists, define owner module, RLS policy, indexes, audit fields, retention
